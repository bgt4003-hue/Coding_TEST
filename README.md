# 설비관리시스템(EAM/CMMS) 웹 설계 기획서

본 문서는 **현장 실무자도 쉽게 사용**하고, **관리자/본사도 운영 현황을 한눈에 파악**할 수 있는 EAM/CMMS 웹 시스템의 정보구조(IA), 화면 구조, UI/UX, 데이터 표현 원칙을 정의합니다.

---

## 1. 전체 사이트맵

> 메뉴 구조는 사용자가 빠르게 찾을 수 있도록 2-depth 중심으로 단순화하고, 모든 핵심 업무(점검/고장/작업오더/예방정비)가 대시보드와 연결되도록 설계합니다.

### 1-1. Global Navigation

- **공통 레이아웃**
  - 좌측: 사이드바 메뉴 (고정)
  - 상단: 공장 선택 / 기간 선택 / 통합 검색 / 알림 / 사용자
  - 우측: 이상 알람 패널(토글)
  - 본문: 페이지별 `필터 영역 + KPI 요약 + 상세 데이터 영역`

### 1-2. 메뉴 트리 (Sitemap)

1) **대시보드**
   - 통합 운영 대시보드
   - 알람/이상징후 센터

2) **설비정보**
   - 설비 목록
   - 설비 상세
     - 기본정보
     - 제원정보
     - BOM
     - 점검이력
     - 작업오더 이력
     - 고장이력
     - 첨부문서/도면

3) **기능위치**
   - 기능위치 트리 조회
   - 기능위치 상세(연결 설비, 이력)

4) **BOM**
   - BOM 목록
   - BOM 상세(상위/하위 구조)

5) **점검관리**
   - 점검계획 조회
   - 점검결과 입력/조회
   - 점검 미이행 관리
   - 모바일 점검 동기화 현황

6) **작업오더**
   - 작업오더 목록
   - 작업오더 상세
   - 승인대기함

7) **고장관리**
   - 고장 접수/처리 현황
   - 원인/조치/재발방지 기록
   - 고장 분석(Pareto / Top10 / 반복고장)

8) **예방정비**
   - 예방정비 캘린더(월/주)
   - 계획 대비 이행 현황
   - 설비별 주기 관리

9) **부품/자재**
   - 자재 마스터
   - 안전재고/소요량
   - 작업오더 사용이력

10) **리포트/분석**
   - KPI 리포트
   - 기간/공정/설비 비교분석
   - 엑셀/PDF 다운로드

11) **관리자 설정**
   - 코드관리(상태/유형/원인코드)
   - 사용자/권한 관리
   - 알림 규칙 설정
   - 마스터 데이터 인터페이스

## 2. 메인 대시보드 와이어프레임 설명

### 2-1. 화면 구조(Desktop 1440px 기준)

```
┌──────────────────────────────────────────────────────────────────────────┐
│ [로고] [공장선택▼] [기간: 이번달▼] [검색]           [알림] [사용자]     │  ← Top Header
├───────────────┬──────────────────────────────────────────────────────────┤
│ 사이드바      │ KPI 카드 6개 (가동률/점검이행률/PM이행률/고장건수/MTBF/MTTR)
│ 메뉴          ├──────────────────────────────────────────────────────────┤
│               │ [월별 고장 추이(라인)] [공정별 비가동 시간(가로바)]       │
│               ├──────────────────────────────────────────────────────────┤
│               │ [설비 상태 분포(도넛)] [부서별 점검 이행률(세로바)]       │
│               ├──────────────────────────────────────────────────────────┤
│               │ 오늘 예정 작업 | 미조치 알람 | 최근 고장 이력 | 긴급 WO   │
└───────────────┴──────────────────────────────────────────────────────────┘
                                      ┌──────────────────────────┐
                                      │ 우측 알람 패널(토글)     │
                                      │ - 고장 발생              │
                                      │ - 점검 미이행 임박       │
                                      │ - 재고 부족              │
                                      └──────────────────────────┘
```

### 2-2. KPI 카드 상세

- 카드 높이 고정(120~140px), 6등분 그리드
- 구성요소
  - 지표명
  - 현재값
  - 전월 대비 증감(▲/▼, %)
  - 기준 임계치 대비 상태 배지(정상/주의/위험)
- 예시
  - 설비 가동률: `92.4% (전월 +1.8%)`
  - MTTR: `3.1h (전월 -0.4h)`

### 2-3. 차트 설계

- 월별 고장 추이: 라인 + 목표선(점선)
- 공정별 비가동 시간: 가로바(내림차순)
- 설비 상태 분포: 도넛(정상/주의/고장)
- 부서별 점검 이행률: 클러스터 바(계획 vs 실적)

### 2-4. 하단 테이블 4종

- **오늘 예정 작업**: 시간, 설비, 작업유형, 담당자, 상태
- **미조치 알람**: 발생시각, 알람유형, 설비, 심각도, SLA 남은시간
- **최근 고장 이력**: 발생일시, 설비, 고장유형, 조치상태
- **긴급 작업오더**: WO번호, 우선순위, 요청부서, 진행상태, 담당

## 3. 주요 화면별 레이아웃 설명

모든 화면 공통 패턴:
1) 상단 필터 영역
2) 중단 요약 KPI/상태 카드
3) 하단 상세 테이블/차트
4) 행 클릭 시 우측 Drawer 또는 상세 페이지 진입

### 3-1. 설비정보

- **필터**: 공장/공정/설비유형/설비상태/제조사/중요도
- **목록 테이블 컬럼**:
  - 설비코드, 설비명, 공장, 공정, 기능위치, 상태, 최근 점검일, 최근 고장일, 담당부서
- **상세 페이지 탭 구성**:
  - 기본정보 / 제원정보 / BOM / 점검이력 / 작업오더 이력 / 고장이력 / 첨부문서·도면
- **UX 포인트**:
  - 상태 배지 색상 통일(정상 녹색, 주의 노랑, 고장 빨강)
  - 최근 고장일이 N일 이내면 경고 아이콘 자동 표시

### 3-2. 기능위치

- 좌측 트리 + 우측 상세 패널 2단 구조
- 트리 노드 선택 시 연결 설비 목록, 최근 작업, 고장 빈도 표시
- 상/하위 기능위치 이동 breadcrumb 제공

### 3-3. BOM

- 상단: 설비/BOM 버전 필터
- 본문: 멀티레벨 BOM 트리 테이블
- 우측: 선택 부품 상세(규격, 대체품, 재고, 최근 사용 WO)

### 3-4. 점검관리

- 탭 구조:
  - 점검계획
  - 점검결과
  - 미이행 목록
  - 모바일 동기화
- **모바일 연동 UX**:
  - 모바일 제출 건은 `MOBILE` 배지
  - 사진 첨부/체크리스트 결과/이상판정 표시
- **강조 규칙**:
  - 이상 발견 항목은 행 전체 옅은 적색 + 좌측 강조 바

### 3-5. 작업오더

- 상태 탭: 생성 / 승인대기 / 진행중 / 완료 / 보류
- 우선순위 필터: 긴급 / 높음 / 보통 / 낮음
- 상세 항목:
  - 작업 요청 내용, 원인, 조치 내용, 사용 부품, 작업시간, 담당자, 완료일, 첨부사진
- 승인 워크플로우:
  - 생성 → 승인대기 → 진행중 → 완료(또는 보류)

### 3-6. 고장관리

- 처리흐름 타임라인:
  - 접수 → 원인분석 → 조치 → 재발방지 → 종결
- 분석 영역:
  - 고장 유형별 분포
  - Pareto 차트(누적비율)
  - Top 10 고장 설비
- 반복고장 자동강조:
  - 최근 90일 동일 유형 3회 이상 시 `반복고장` 플래그

### 3-7. 예방정비

- 캘린더 뷰(월/주 전환)
- 카드에 설비, 작업유형, 예정일, 담당, 이행상태 표시
- 미이행 건 상단 고정 위젯으로 별도 노출
- 설비별 주기 테이블(주기, 최근 수행일, 차기 예정일)

### 3-8. 부품/자재

- 재고현황 KPI: 총 품목, 안전재고 미달, 이번달 사용량
- 품목 테이블 + 안전재고 경고
- WO별 자재 사용량 드릴다운

### 3-9. 리포트/분석

- 템플릿 리포트: 월간 설비 성과, 공정별 고장 분석, 부서별 점검 이행
- 비교분석: 전월/전분기/전년 동기 비교
- 출력: 엑셀/PDF/이미지

### 3-10. 관리자 설정

- 권한 기반 메뉴 제어(Role-based)
- 코드 테이블 관리 UI(추가/수정/비활성)
- 알림 임계치 룰 설정(예: MTTR>4h 경보)

## 5. 사용자 동선 시나리오

### 시나리오 A: 현장 설비관리자(빠른 조치 중심)

1. 로그인 후 대시보드에서 `긴급 작업오더` 카드 확인
2. 긴급 WO 클릭 → 작업오더 상세 진입
3. 원인/필요 부품 확인 후 담당자 배정
4. 처리 중 상태 업데이트 + 사진 첨부
5. 완료 처리 후 고장관리 탭에서 재발방지 등록

### 시나리오 B: 정비 담당자(점검/작업 수행 중심)

1. 점검관리 > 오늘 점검계획 조회
2. 모바일 점검 결과 동기화 내역 확인
3. 이상 항목(빨간 강조행) 우선 조치 WO 생성
4. 작업오더에서 사용 부품/작업시간 입력 후 완료

### 시나리오 C: 공장 관리자(운영 모니터링 중심)

1. 대시보드 KPI(가동률/MTBF/MTTR) 확인
2. 공정별 비가동 시간 차트에서 문제 공정 식별
3. 고장관리의 Pareto로 상위 원인 파악
4. 예방정비 캘린더에서 다음 주 미이행 리스크 점검

### 시나리오 D: 본사 운영/기획(비교분석 중심)

1. 리포트/분석에서 공장별 KPI 비교
2. 월간 추이 보고서 엑셀 다운로드
3. 관리자 설정에서 점검 이행률 임계치 재설정

## 6. 화면별 예시 텍스트

### 6-1. 대시보드

- 페이지 타이틀: `통합 설비 운영 대시보드`
- 보조문구: `실시간 운영 상태와 핵심 리스크를 확인하세요.`
- 배너: `주의: 금일 점검 미이행 12건, 18:00 전 조치 필요`

### 6-2. 설비정보

- 검색 플레이스홀더: `설비코드/설비명/기능위치 입력`
- 빈 상태 문구: `조건에 맞는 설비가 없습니다. 필터를 조정해 주세요.`

### 6-3. 점검관리

- 섹션 제목: `미이행 점검 목록`
- 강조 라벨: `이상 발견`, `재점검 필요`, `모바일 접수`

### 6-4. 작업오더

- 버튼: `작업오더 생성`, `승인 요청`, `완료 처리`
- 상태 힌트: `보류 상태는 보류 사유 입력이 필수입니다.`

### 6-5. 고장관리

- 섹션 제목: `반복고장 설비 (최근 90일)`
- 안내문구: `동일 원인 반복 시 재발방지 대책 등록이 필요합니다.`

### 6-6. 예방정비

- 탭: `월간 계획`, `주간 계획`, `미이행 현황`, `주기 기준표`
- 안내문구: `주기 초과 설비는 우선순위가 자동 상향됩니다.`

## 7. 프론트엔드 구현용 프롬프트

다음 프롬프트를 사용하면 UI 시안(React 기준)을 빠르게 생성할 수 있습니다.

```text
당신은 시니어 프론트엔드 엔지니어입니다.
React + TypeScript + Tailwind + shadcn/ui 기반으로
EAM/CMMS 대시보드 웹을 구현하세요.

요구사항:
- 다크 테마 엔터프라이즈 UI
- 좌측 사이드바(11개 메뉴), 상단 헤더(공장선택/기간선택/알림/사용자)
- 페이지 공통 구조: 검색필터 + KPI 카드 + 차트 + 테이블
- 대시보드 KPI: 가동률, 점검 이행률, 예방정비 이행률, 고장건수, MTBF, MTTR
- 차트 4종: 월별 고장추이(line), 공정별 비가동시간(bar), 상태분포(donut), 부서별 점검이행률(bar)
- 테이블 4종: 오늘 예정작업, 미조치 알람, 최근 고장이력, 긴급 작업오더
- 테이블 기능: 정렬/필터/페이징/엑셀 다운로드 버튼
- 상태 색상: 정상(녹색), 주의(노랑), 고장/긴급(빨강)
- 작업오더 상태: 생성/승인대기/진행중/완료/보류
```

## 8. 디자이너/개발자 전달용 상세 가이드

### 8-1. 정보 우선순위 원칙

- 1순위: 위험/긴급/미이행 (즉시 행동 필요)
- 2순위: 당일 작업/점검 실행 항목
- 3순위: 추세 분석/성과 지표
- 따라서 색상, 위치, 크기 모두 1순위 정보에 집중 배치

### 8-2. 그리드/간격

- 기본 12-column 그리드
- 좌우 마진 24px, 카드 간격 16px, 섹션 간격 20~24px
- KPI 카드 동일 높이 유지(시각적 안정성)

### 8-3. 타이포그래피

- 제목: 20/24 semibold
- 섹션: 16/20 semibold
- 본문: 14/20 regular
- 표 숫자: tabular-nums 권장(정렬 가독성)

### 8-4. 테이블 UX 표준

- 헤더 고정(sticky)
- 가로 스크롤 시 첫 1~2열 고정
- 행 hover + 선택 상태 명확화
- 컬럼별 빠른 필터
- 다운로드(엑셀) 버튼 우측 상단 고정

### 8-5. 알람/이상징후 정책

- `Critical`: 빨간 배경 배너 + 알림음 옵션
- `Warning`: 노란 배지 + 우측 패널 누적
- 미조치 SLA 임박 순 정렬

### 8-6. 반응형 정책(태블릿)

- 1440px+: 4열 카드/2열 차트
- 1024~1439px: 3열 카드/1~2열 차트
- 768~1023px: 카드 2열, 테이블은 핵심 컬럼 우선 + 상세는 Drawer

### 8-7. 접근성/사용성

- 상태를 색상만으로 전달하지 않고 아이콘/텍스트 병행
- 버튼/필터 최소 높이 40px
- 키보드 포커스 가시화, 표준 ARIA 라벨 준수

### 8-8. 확장 고려

- 다공장/다국어 대응을 위한 공장·조직 코드 표준화
- 차후 IoT 센서 연동 시 실시간 스트림 카드 확장 가능
- API 응답 지연 대비 스켈레톤 로딩/부분 갱신 구조 채택
